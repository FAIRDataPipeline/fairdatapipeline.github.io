                                Schema Description#

                                The FAIR data registry schema records the data and the code of a modelling pipeline, and how they are connected, so that every result can be traced back to the code run that produced it and the inputs that it read.

                                Every table is available through the registry’s REST API (e.g. /api/data_product/), where the description of each table lists its fields.

                                Data#

                                graph LR;
    EO(ExternalObject) -- original_store --> SL(StorageLocation)
    DP(DataProduct) -- external_object --> EO
    DP -- namespace --> NS(Namespace)
    DP -- object --> O(Object)
                                • DataProduct: A dataset that is used by or generated by a model, identified by its name, version (semantic versioning) and Namespace. Once registered, its name, version, object and namespace cannot be changed.
                                • Namespace: A way to group DataProducts, for example by the organisation that produces them, with a unique name and full_name and an optional website.
                                • ExternalObject: Data that comes from somewhere other than the pipeline, such as a published dataset or paper. It is identified by an identifier (e.g. a DOI), or by an alternate_identifier with its alternate_identifier_type, together with its title and version, so a new release of a source is a new ExternalObject. It also records the release_date, whether it is a primary source (primary_not_supplement), and optionally the original_store it was copied from. Each DataProduct registered from it points to it through external_object, so one ExternalObject can have several DataProducts.

                                Code runs#

                                graph LR;
    CR(CodeRun) -- code_repo --> O1(Object)
    CR -- model_config --> O2(Object)
    CR -- submission_script --> O3(Object)
    CR -- inputs --> OC1(ObjectComponent)
    CR -- outputs --> OC2(ObjectComponent)
    CRR(CodeRepoRelease) -- object --> O1
                                • CodeRun: A run of a model, with its run_date, description and uuid. It points to the Objects for the code repository (code_repo), the working configuration (model_config) and the submission script, and lists the ObjectComponents it read (inputs) and wrote (outputs). An output has only one producing CodeRun, and a CodeRun cannot read anything produced downstream of its own outputs.
                                • CodeRepoRelease: Marks that an Object is an official release of model code, with a name and version (unique together) and an optional website.

                                FAIR objects#

                                graph LR;
    O(Object) -- storage_location --> SL(StorageLocation)
    SL -- storage_root --> SR(StorageRoot)
    O -- file_type --> FT(FileType)
    O -- authors --> A(Author)
    UA(UserAuthor) -- author --> A
    OC(ObjectComponent) -- object --> O
    OC -- issues --> I(Issue)
    L(Licence) -- object --> O
    K(Keyword) -- object --> O
    KV(KeyValue) -- object --> O
    QC(QualityControlled) -- object --> O
                                • Object: The core traceability record behind every file: DataProducts, code repositories, configurations and submission scripts all point to an Object. It has a uuid, an optional description, and optionally a StorageLocation, a FileType and a list of Authors.
                                • ObjectComponent: A named part of an Object, such as a table within a file. These are what CodeRuns read and write. Each Object automatically gets a component called whole_object (with whole_object set to true) that represents the whole object.
                                • Issue: A quality issue attached to one or more ObjectComponents, with a severity (larger is more severe) and a description. An issue with a whole object is attached to its whole_object component.
                                • StorageLocation: The location of a file, given as a path relative to a StorageRoot, with the SHA-1 hash of the file and whether it is public. A file is stored once per StorageRoot: the combination of storage_root, hash and public is unique.
                                • StorageRoot: The root of a store where files are kept, given as a URI such as https://somewebsite.com/, file:///someroot/ or github://org:repo@sha/, and whether it is local. Appending a StorageLocation’s path to the root gives the full address of the file.
                                • FileType: The name and extension of a type of file, e.g. Comma-separated values file and csv.
                                • Author: A creator of an Object, with a name and/or an identifier (such as an ORCID or ROR ID).
                                • UserAuthor: Links a registry user to the Author that represents them.
                                • Licence: The licence of an Object, as free text (licence_info) and optionally an identifier URL.
                                • Keyword: A keyphrase describing an Object, e.g. the keywords of a paper, optionally with the identifier of an ontology term.
                                • KeyValue: Free metadata about an Object as a key and a value, with each key used once per Object.
                                • QualityControlled: Marks that an Object has been quality controlled, pointing to the Object of the quality control document.

                                Internal provenance#

                                Every table also records who last changed each record (updated_by) and when (last_updated). These fields are set by the registry and cannot be written through the API.
